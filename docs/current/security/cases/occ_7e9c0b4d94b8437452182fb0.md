# Cartridge bounds fix omits word-rounded direct-boot reads

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_7e9c0b4d94b8437452182fb0` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The current cartridge validator checks that each declared ARM section's byte range fits the ROM, but the NDS and DSi direct-boot loaders read every section in four-byte words while testing only 'i &lt; declaredSize'. If a section size is not divisible by four and its declared end equals the end of an exact-power-of-two ROM, the final native 'u32' dereference reads one to three bytes past the allocation.
- **Attack path:** Malicious header offsets/sizes -&gt; byte-range validator -&gt; exact ROM allocation -&gt; word-stepped loader -&gt; native over-read -&gt; guest ARM memory.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static comparison of current cartridge bounds against every native word read in Android-reachable direct-boot loaders.; Validator accepts declared byte ranges without word rounding; 'offset + size == length' is accepted for any byte size; neither alignment nor a checked round-up to the four bytes consumed by… Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Most non-power-of-two ROMs receive a larger padded allocation, avoiding an allocation-boundary over-read on this subpath. The over-read is only one to three bytes.
- **Limitations:** No ASan Android/host reproduction was run; adjacent allocation contents are runtime-dependent. No crafted image was executed.
- **Recommended correction:** Either require every directly loaded ARM/ARM9i/ARM7i size and offset to satisfy the loader's alignment contract, or validate a checked 'round_up(size,4)' range and define deterministic fill for partial words. Prefer copying the last partial word bytewise into a zero-initialized local 'u32'. Apply the same rule to NDS and DSi paths before retaining the cartridge.
