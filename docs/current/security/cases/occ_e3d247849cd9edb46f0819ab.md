# RetroAchievements HTTP errors leak response resources across repeated requests and retries

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_e3d247849cd9edb46f0819ab` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** 'RAApi.executeRequest()' transfers successful responses to callers that close their readers, but every non-success branch resumes with an exception without closing the OkHttp 'Response' or body.
- **Attack path:** Pending submission -&gt; 'RAApi' POST -&gt; non-success OkHttp 'Response' -&gt; exceptional continuation without close -&gt; two-minute retry -&gt; accumulated transport resources
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static response-lifecycle and retry-state trace; Delivered success body reader is closed by the caller; The success branch eventually wraps the response body reader in 'use', releasing that body after materialization. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The retry interval limits the accumulation rate. The endpoint is fixed HTTPS and the integration is optional.
- **Limitations:** No runtime descriptor, connection-pool, or heap measurement was performed. OkHttp dependency code outside the repository was not treated as an affected implementation.
- **Recommended correction:** Use one exactly-once response-ownership helper: close every non-success response before exceptional resume, preferably with 'response.use'/'try-finally', while transferring only successful responses to a bounded downstream decoder. Cover token clearing, coroutine cancellation races, ordinary requests, and the two-minute submission retry path.
