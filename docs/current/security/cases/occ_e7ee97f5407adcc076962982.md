# Savestate-restored multiplayer reply lengths overflow the native Wi-Fi receive buffer

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_e7ee97f5407adcc076962982` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** A selected savestate restores the complete Wi-Fi multiplayer reply slots together with a pending phase-two command reply. The semantic restore checks validate TX descriptors, phases, masks and countdowns, but not the 16-bit length embedded in each 1,024-byte reply slot.
- **Attack path:** selected savestate -&gt; 'MelonDS::loadState' -&gt; 'Wifi::DoSavestate' restores pending reply -&gt; Wi-Fi timer 'ProcessTX' -&gt; 'MPClientReplyRX' -&gt; unbounded native copies
- **Evidence and proof level:** **static** in the sealed finding (`status not specified`): Static source trace through the production Android savestate loader and resumed Wi-Fi timer; Android accepts a selected state after deserialization reports success; File framing and a 128 MiB cap exist, but an internally consistent Wi-Fi section is accepted whenever its component validation leaves… Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Android retains DummyMP, so ordinary malicious multiplayer network delivery was not established. The savestate path bypasses that limitation by restoring both pending phase and reply data.
- **Limitations:** No application execution, sanitizer reproduction, or reliable code-execution demonstration was performed.
- **Recommended correction:** When loading a state, validate every reply that can be pending: client index, complete header, nonnegative crop result, payload within the 1,024-byte slot, and final copy length within 'RXBuffer'. Repeat the same bounds checks immediately in 'MPClientReplyRX' before either copy and reject the state on failure.
