# Untrusted serialized ROM configurations expose or overwrite files using melonDS authority

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_0ead515f26677112d1f828d6` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `high` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The exported, unpermissioned 'EmulatorActivity' accepts a caller-created 'RomParcelable', while manual settings restore copies attacker-supplied 'rom_data.json' into app-private cache state. Both rich serialized configurations can supply nested GBA ROM and save locations that are forwarded through JNI without re-establishing ownership or current grants.
- **Attack path:** external Parcelable -&gt; trusted 'Rom' config -&gt; raw nested path -&gt; target-UID native open -&gt; GBA cartridge memory -&gt; malicious NDS -&gt; provider-backed SRAM -&gt; attacker
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static trace of the forged Parcelable from exported activity to native private-file open, guest cartridge mapping, SRAM write, and attacker-readable persistence; The emulator launch activity is exported without a permission; Another installed application can explicitly start the component and… Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — exported launch and read-grant tests pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Modern Android can restrict background activity starts; an attacker can still initiate from a foreground activity or user gesture. Switching an already-running emulator session prompts the user, but a fresh exported launch does not.
- **Limitations:** The scan did not dynamically marshal the Parcelable across package boundaries. The exact private preference filename varies by applicationId suffix, but the installed package name is observable and the production path is deterministic.
- **Recommended correction:** Do not accept 'RomParcelable', 'KEY_ROM', or any rich internal 'Rom' object from an exported component; expose only a narrow URI contract and reconstruct configuration from trusted repository state or fresh SAF selections. Do not back up or restore derived 'rom_data.json'; rebuild it from currently authorized ROM trees, or discard every nested GBA path until the user reselects it.
