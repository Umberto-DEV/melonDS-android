# Exhausted guest DHCP leases leak native reply buffers on every subsequent request

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_2cbc1cd3c17db642b326d34c` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android installs the bundled 'Net_Slirp' driver with configuration version 1, which leaves DHCP enabled. 'bootp_reply' allocates a reply mbuf before selecting a lease; guest-controlled hardware addresses can fill all 16 lease entries, after which each DHCPDISCOVER from a new address returns without freeing the newly allocated reply.
- **Attack path:** malicious ROM -&gt; guest broadcast DHCPDISCOVERs with distinct MACs -&gt; 16-entry lease pool exhausted -&gt; 'm_get' reply allocation -&gt; unmatched return -&gt; retained 'm_usedlist' growth
- **Evidence and proof level:** **static** in the sealed finding (`status not specified`): Static ownership and production-deployment trace; Android installs DHCP-enabled bundled SLIRP; Every Android emulator run configures the bundled SLIRP network driver. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Slirp destruction eventually frees the used list, so growth is scoped to one networking-context lifetime. The attacker must run guest code capable of emitting valid DHCP packets; unsolicited remote LAN traffic is not the entry point.
- **Limitations:** The exact packet rate and memory-exhaustion time depend on device memory and emulator scheduling.
- **Recommended correction:** Select or reserve the lease before allocating a reply, or call 'm_free(m)' on the no-address branch. Audit every post-allocation early return in the bundled BOOTP/DHCP path and keep ownership explicit.
