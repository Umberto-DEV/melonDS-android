# A crafted DSi ROM can overflow a host stack buffer through unaligned NAND block transfers

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_c4615d109e2957a6c04ff773` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The emulated DSi SD/MMC controller accepts a guest-provided byte address while NAND remains byte-addressed, then processes up to 512 bytes through '&data[addr & 0x1ff]' in a fixed 512-byte stack array. Transfer length is capped but the complete offset-plus-length window is not, and DataRX/DataTX advance in two-byte units.
- **Attack path:** guest ARM7 SD/MMC MMIO -&gt; command parameter and BlockSize -&gt; NAND raw-byte RWAddress -&gt; unchecked 'data + (addr & 0x1ff)' -&gt; FileRead/DataTX native write Additional corroboration: guest ARM7 SD/MMC registers -&gt; 'DSi_SDHost::Write()' -&gt; 'DSi_MMCStorage::SendCMD()' -&gt; incomplete 'GetTransferrableLen()' -&gt; offset stack pointer -&gt; 'FileRead()' or…
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static source trace of DSi ARM7 MMIO, MMC command state, NAND addressing, and native read/write buffers Additional corroboration: Offline source trace and exact span arithmetic; no emulator code executed.; Guest writes control SD/MMC registers; DSi ARM7 writes reach the shared Android-compiled… Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The transfer length is capped at 512 bytes, but that does not protect a nonzero offset. SDHC-style addressing aligns addresses, but internal NAND explicitly prevents that mode.
- **Limitations:** Static validation only; the authorized scan did not execute a crafted ROM. Exact corruption outcome depends on compiler stack layout.
- **Recommended correction:** Validate the complete transfer window at every sink with checked arithmetic, requiring 'offset &lt;= sizeof(data)' and 'roundUp(len, 2) &lt;= sizeof(data) - offset' for FIFO paths. Reject or normalize unaligned full-block NAND byte addresses, or split intentional cross-sector operations into bounded chunks.
