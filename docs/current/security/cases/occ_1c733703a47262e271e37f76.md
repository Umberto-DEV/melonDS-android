# Invalid DSi camera dimensions create an endless zero-delay event loop

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_1c733703a47262e271e37f76` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Guest-writable camera MCU registers can configure an invalid positive-height frame. The camera scanline routine then returns zero lines without advancing transfer state; the module computes a zero delay, sees the transfer as unfinished, and reschedules the same event at the current timestamp. The native frame runner repeatedly dispatches it without emulated-time or frame progress.
- **Attack path:** guest MCU width/height -&gt; StartTransfer -&gt; zero-progress TransferScanline -&gt; delay 0 -&gt; ScheduleEvent -&gt; NextTarget/RunSystem loop
- **Evidence and proof level:** **static** in the sealed finding (`status not specified`): independent baseline plus parent static control-flow trace; Camera dimensions come from guest-writable MCU registers; Guest I2C camera writes update MCURegs, and StartTransfer copies their width and height into the live transfer. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Valid dimensions advance the transfer. FrameHeight zero completes immediately, so the trigger uses a positive height with another invalid dimension.
- **Limitations:** No CPU-usage measurement or runtime reproduction was performed. CPU consumption and Android UI behavior were not measured at runtime.
- **Recommended correction:** Reject invalid dimensions before starting capture, or mark the transfer complete/error when scanline generation cannot advance. Never reschedule an unfinished event with zero delay unless another state transition guarantees progress; add a scheduler or subsystem forward-progress assertion.
