# Guest-writable firmware metadata reaches unchecked host buffer copies

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_199e211e1856d6a8fcbf97fa` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Firmware SPI command 0x0A lets the emulated guest modify every byte of the firmware buffer, including 'Identifier' and 'UserSettingsOffset'. On command release, the core derives an unchecked Wi-Fi offset and subtracts it from the firmware length. Android chooses the persistence buffer based on the guest-writable identifier, and 'SaveManager::RequestFlush()' uses wrapping 32-bit offset arithmetic before 'memcpy'.
- **Attack path:** guest SPI bytes -&gt; mutable firmware header -&gt; unchecked Wi-Fi offset/subtraction -&gt; Android persistence callback -&gt; wrapping range check -&gt; 'memcpy'
- **Evidence and proof level:** **static** in the sealed finding (`validated`): static state-machine and unsigned-arithmetic trace; Guest can rewrite any firmware byte; The mask keeps this write inside the current allocation but permits the guest to alter header fields later trusted as offsets and policy. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — layout/provider-length controls pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The original SPI byte write is masked into the firmware allocation; the vulnerability appears when the modified bytes are used as metadata.
- **Limitations:** No emulator PoC or sanitizer trace was executed.
- **Recommended correction:** Treat every firmware-derived offset as untrusted. Validate 'wifioffset &lt;= firmware.Length()' before subtraction, keep the persistence mode independent of guest-writable identifier bytes, and make 'RequestFlush()' require 'writeoffset &lt;= savelen' and 'writelen &lt;= savelen - writeoffset' before any copy. Handle legitimate circular writes only with separately validated segments.
