# Closing the DSiWare screen can free NAND state while title enumeration is still running

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_95f95be3047a6de20473771d` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Serialize DSi NAND teardown with every operation that uses the native NAND globals. The manager protects open, list, import, delete and export with a mutex, but closeNand bypasses it; ViewModel teardown can therefore call native close while a non-cancellable JNI list operation still dereferences nandMount, causing a native use-after-free and process crash or memory corruption.
- **Attack path:** A format-aware attacker supplies a DSi NAND image with enough valid title entries to prolong enumeration. After the user opens the DSiWare manager, leaving the screen during enumeration can run onCleared concurrently with JNI, freeing the active mount.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static source-backed synchronization and native lifetime trace; List operation holds nandControlLock; All of listTitles, including the blocking JNI invocation, executes under nandControlLock. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** viewModelScope cancellation reduces the window, but does not preempt a JNI function already executing. The atomic usage count protects multiple holders from ordinary early close, but does not serialize final destruction with an in-flight operation.
- **Limitations:** No runtime race harness, sanitizer execution, or device reproduction was performed. Reliability and exploitability depend on scheduler timing and allocator behavior.
- **Recommended correction:** Unify DSi NAND ownership and operation lifetime under one synchronization mechanism. Make final release wait for nandControlLock (or use a lease/in-flight-operation guard) before clearing isNandOpen and invoking native close, prevent usage-count underflow, and do not rely on coroutine cancellation to stop JNI.
