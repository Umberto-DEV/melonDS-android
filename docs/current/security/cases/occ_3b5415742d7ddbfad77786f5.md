# A malicious document provider can turn firmware revalidation drift into a controlled heap overwrite

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_3b5415742d7ddbfad77786f5` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `high` · layer `cross`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android validates custom firmware through one 'AssetFileDescriptor', accepting only 0x20000, 0x40000, or 0x80000 bytes, but emulator setup later reopens the same content URI through a fresh provider descriptor. The native 'Firmware' constructor caps its allocation at 0x80000 while passing the newly observed, unclamped file length to 'FileRead'.
- **Attack path:** Provider descriptor A (valid size) -&gt; preflight passes -&gt; provider descriptor B (oversized) -&gt; 512 KiB allocation -&gt; full-length read
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static cross-layer TOCTOU trace from Android SAF preflight through a second provider open to the native allocation/read mismatch.; Preflight validates the length of one provider descriptor; 'FirmwareValidation' accepts only 0x20000, 0x40000, or 0x80000 for DS firmware, but this descriptor is closed after the… Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — drift and invalid flush-range controls pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** A stable ordinary firmware file of one of the three supported sizes does not trigger this overflow. The normal Android preflight rejects an oversized stable descriptor.
- **Limitations:** No malicious DocumentsProvider proof of concept was executed. Reliable code execution was not demonstrated, though the controlled heap overwrite is direct.
- **Recommended correction:** At the native constructor, reject any current descriptor length other than the supported exact firmware sizes before allocating or reading, and always cap the read to the allocation. Prefer copying and validating provider content once into an app-owned immutable file or retaining the already-validated descriptor through consumption.
