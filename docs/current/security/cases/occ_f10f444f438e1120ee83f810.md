# R4 data commands expose an uninitialized native heap buffer to guest code

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_f10f444f438e1120ee83f810` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** A ROM whose header selects CartR4 can issue B3 or BA before any successful SD read. CartR4's 512-byte member buffer is neither value-initialized nor cleared by Reset, yet both commands copy it into the guest-visible transfer buffer without checking BufferInitialized. This exposes allocator residue from the Android emulator process to malicious guest code.
- **Attack path:** Attacker ROM header and cartridge commands -&gt; CartR4 selection and ROMCommandStart -&gt; uninitialized Buffer read -&gt; TransferData -&gt; guest ROM data register.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Offline source-to-sink validation of the current nested core and Android configuration.; R4 buffer has no initializer; The guest-readable Buffer is raw object storage with no in-class value initializer. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** TransferData is initialized to 0xFF before dispatch, but B3/BA overwrite it with Buffer. B7 checks BufferInitialized, but that guard does not cover B3 or BA.
- **Limitations:** No runtime exploit or allocator-content sample was produced because execution was prohibited.
- **Recommended correction:** Value-initialize Buffer and clear it on Reset. Require BufferInitialized before B3, BA, B7 and BF; clear Buffer before every attempted I/O and set BufferInitialized only after an exact successful read. Return deterministic zero/error data when invalid.
