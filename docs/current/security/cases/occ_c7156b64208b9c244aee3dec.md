# GPU3D savestate restoration trusts array indices and counts before native writes

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_c7156b64208b9c244aee3dec` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** GPU3D::DoSavestate restores vertex/polygon indices and geometry counters directly from a savestate into fixed native arrays. It immediately forms unchecked pointers and dereferences up to attacker-controlled Polygon::NumVertices, then resumes emulation with attacker-controlled NumPolygons and NumOpaquePolygons. The next VBlank can read beyond PolygonRAM and write beyond RenderPolygonRAM[2048].
- **Attack path:** crafted GP3D section -&gt; Var32 indices/counts -&gt; GPU3D live pointers/state -&gt; resumed VBlank -&gt; PolygonRAM/RenderPolygonRAM out-of-bounds access
- **Evidence and proof level:** **static** in the sealed finding (`validated`): static source trace; GPU array counts are restored without bounds; Savestate values become live pointers and loop/write bounds without comparison to PolygonRAM, VertexRAM or RenderPolygonRAM sizes. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — GPU semantic invariant tests and core sanitizer build pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The user must explicitly load a matching crafted state file. Normal polygon construction checks per-bank limits, but state loading bypasses those construction-time checks.
- **Limitations:** No concrete code-execution chain or device crash reproduction was produced. Other restored subsystems may contain similar unchecked invariants; this finding records the validated GPU/FIFO pattern only.
- **Recommended correction:** After deserialization and before any pointer construction or emulation resume, validate every GPU invariant: vertex indices &lt; 12288 or sentinel, polygon indices &lt; 4096 or sentinel, Polygon::NumVertices &lt;= 10, NumVertices within the active bank, NumPolygons/NumOpaquePolygons/RenderNumPolygons &lt;= 2048 with consistent ordering, and all sort ranges within RenderPolygonRAM.
