# Failed savestate loads leave partial state because the backup is never switched to load mode

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_277d6d22695d3f279a0df1f1` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Before loading an untrusted savestate, Android serializes a backup into a Savestate object. If the load fails, it passes that same finished, Saving=true object to loadState without Rewind(false). Savestate operations then no-op or follow save branches, NDS::DoSavestate returns success, and the wrapper logs that the backup loaded even though partially mutated emulator state remains.
- **Attack path:** Untrusted state -&gt; partial live mutations -&gt; later error -&gt; malformed backup restore -&gt; no-op -&gt; partial state retained.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Manual failure-path and state-machine trace.; Backup reused without rewind; The backup is serialized and finished, then passed straight back to the load wrapper without changing mode or offset. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** File size and structural checks occur before or during the untrusted load but do not restore prior mutations after later semantic failure. The caller returns false, but source does not reconstruct or stop the emulator instance in this function.
- **Limitations:** Runtime/UI behavior after the false return was not executed; exact persisted partial fields depend on where parsing fails. The persistence timing of 'Platform::WriteNDSSave' may be buffered by the platform save manager, but the call and live SRAM mutation occur before rejection.
- **Recommended correction:** Call backup-&gt;Rewind(false) immediately before each rollback and treat rollback failure as terminal for the emulator instance. Prefer two-phase deserialization into temporary state followed by atomic commit so failed loads never mutate live state.
