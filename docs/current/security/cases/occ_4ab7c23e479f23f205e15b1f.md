# Savestate file length drives an uncapped native allocation before validation

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_4ab7c23e479f23f205e15b1f` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Save-state slots are discovered by exact '.ml0'–'.ml8' filenames in the configured save-state tree. When the user loads a matching provider-backed, sparse, oversized, or length-misreported slot, native code has already created its rollback backup and then constructs 'std::vector&lt;u8&gt;(size)' from the untrusted file length before checking MELN magic, version, embedded length, or any maximum.
- **Attack path:** configured save directory -&gt; matching slot URI -&gt; native whole-file read -&gt; attacker-controlled savestate field -&gt; unsafe parser/allocation operation
- **Evidence and proof level:** **static** in the sealed finding (`validated`): independent static source trace; File length is allocated before format validation; No maximum or allocation-failure handling precedes whole-file allocation; format validation is later. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — invalid length checks run before vector allocation. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The user must launch the associated ROM and select the crafted state. App-private save directories are not normally writable by another unprivileged app.
- **Limitations:** No crafted savestate was executed. No oversized state was loaded on a device.
- **Recommended correction:** Define a conservative maximum serialized-state size and reject unknown, zero, failed, or oversized lengths before allocation. Validate a fixed header and declared size first, use checked size conversions, read through a bounded stream, and catch allocation/length errors entirely in native code so load returns 'false' across JNI.
