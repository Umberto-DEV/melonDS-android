# R4 guest commands dereference SD storage that Android intentionally omits

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_5830142954786d70a8044c22` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android constructs cartridge arguments with 'SDCard = nullopt', yet an R4-shaped ROM still selects 'CartR4'; reset records the missing card but leaves storage commands enabled. Guest command '0xB4' unconditionally calls 'SD-&gt;ReadSectors'. Command '0xBF' with a transfer of at least 512 bytes reaches 'GetEncryptionKey', which unconditionally calls 'SD-&gt;ReadFile'.
- **Attack path:** Optional dependency is missing but command remains active.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent Android configuration and guest-command dispatch trace Additional corroboration: Offline effective-configuration and guest-command source trace.; Android disables cartridge SD backing; The scoped Android frontend always provides no SD object to ParseROM. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Ordinary R4 firmware may honor InitStatus and avoid B4, but malicious guest code is not constrained by that convention. B9 has a guard, proving no global dispatch check protects B4.
- **Limitations:** No Android crash reproduction was executed. No runtime crash fixture executed.
- **Recommended correction:** Guard every R4 storage-dependent path, including '0xB4', '0xBF', and 'GetEncryptionKey', with SD-presence checks. Return deterministic error or zero-filled protocol data when storage is absent, and preferably disable all storage commands centrally whenever initialization records no SD backing.
