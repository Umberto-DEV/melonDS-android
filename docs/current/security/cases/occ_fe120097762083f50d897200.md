# Android JNI entrypoints leak UTF string leases across repeated operations

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_fe120097762083f50d897200` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Configuration setup, ROM launch, firmware configuration, and save-state entrypoints acquire UTF-8 pointers from Java strings without reliably releasing them. Configuration paths and the internal directory are retained as raw JNI lease pointers and lost when configuration is replaced; other paths reuse one 'isCopy' output across independent acquisitions or omit release entirely.
- **Attack path:** Java String/Uri -&gt; GetStringUTFChars -&gt; raw pointer or conditionally released local -&gt; operation returns/reconfiguration -&gt; lease ownership lost
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent source review followed by ownership and call-site validation; Configuration acquires persistent UTF leases; Up to eight Java strings are acquired and their lease pointers are stored directly in the returned configuration without any matching release. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Each individual path or firmware string is small. Retaining configuration leases avoids an immediate dangling pointer; the observed primitive is a leak, not use-after-free.
- **Limitations:** Static offline analysis; VM-specific leak growth was not measured.
- **Recommended correction:** Copy every acquired UTF string into 'std::string' before the JNI call returns and wrap each 'GetStringUTFChars' result in an RAII lease that unconditionally invokes 'ReleaseStringUTFChars' on the same 'jstring'. Track acquisition failure and each string independently; make configuration path fields owning strings.
