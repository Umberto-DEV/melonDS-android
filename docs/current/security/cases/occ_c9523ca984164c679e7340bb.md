# Savestate SRAM lengths drive unbounded cartridge allocations

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_c9523ca984164c679e7340bb` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Both NDS CartRetail and GBA CartGame overwrite the active cartridge's SRAMLength from savestate input and allocate that serialized size before Savestate::VarArray validates the payload. Neither load path requires the value to match the current cartridge or a supported save-memory size.
- **Attack path:** A ROM-matching crafted state reaches the appropriate cartridge section and supplies an excessive SRAM length, causing native heap exhaustion.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent inspection of NDS/GBA DoSavestate consumers and the shared VarArray control.; NDS state length replaces the active SRAM length; A differing attacker value is explicitly accepted and allocated before its bytes are checked. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — mismatched length is rejected; valid state remains fixed-size. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Earlier core state checks require a state tailored to the current ROM/cartridge. VarArray later notices missing bytes, but allocation has already occurred.
- **Limitations:** No separate item was recorded in the sealed finding.
- **Recommended correction:** Do not overwrite the active cartridge SRAM length during load. Require the serialized value to equal the expected current size and a strict NDS/GBA supported-size allowlist before any allocation or read; fail the state otherwise.
