# GBA flash commands read and overwrite host heap beyond save RAM

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_0f5f2f5c076ab2aa0094b993` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** When an Android user attaches a GBA ROM/save, the emulated DS guest can issue flash commands to that cart. The flash bank command accepts any byte, reads add the unchecked bank to the guest address, and sector erase writes 0x1000 bytes from an unaligned guest-selected address.
- **Attack path:** guest GBA-slot bus commands -&gt; flash state machine -&gt; unchecked bank/address arithmetic -&gt; 'SRAM' heap access
- **Evidence and proof level:** **static** in the sealed finding (`validated`): static source trace with concrete address calculation; Android forwards configured GBA URIs; The Android product exposes the GBA-cart configuration that makes the native flash implementation reachable. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — both flash sizes and boundary controls pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Top-level SRAM bus addresses are masked to 16 bits and ordinary SRAM byte writes are bounded; the later bank addition and erase span bypass those controls. Ordinary A0 program-byte writes are bounded.
- **Limitations:** No live guest PoC or exploit chain was run. Validation was static because the read-only scan environment did not permit building an instrumented APK.
- **Recommended correction:** Restrict bank selection to valid banks for the detected flash type, align sector erases to the hardware sector boundary, and validate every read/write span against 'SRAMLength' using overflow-safe subtraction before accessing 'SRAM'. Reject or safely emulate unsupported save sizes.
