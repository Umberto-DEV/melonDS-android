- **Summary:** The corrected DAT parser bounds one address book at 100,000 entries, one game block at 1 MiB, and one cheat code at 1 MiB, but it never applies an import-wide budget. Positive signed offsets can drive close to 2 GiB of provider reads, and every parsed game is inserted inside one Room transaction.
- **Attack path:** A selected malicious content provider or sparse DAT exposes a valid address book with many increasing offsets and game records; import reads toward those offsets and inserts each result before any aggregate quota stops it.

- **Counterevidence:** Individual game blocks and cheat-code byte arrays are capped. The channel buffers only four games concurrently.
- **Limitations:** No multi-gigabyte sparse or generated provider fixture was executed; exact device storage amplification is unmeasured.
- **Recommended correction:** Define conservative import-wide maxima for source bytes, address-book entries, games, folders, cheats, total code/text bytes, and expected Room rows. Reject known descriptor lengths before parsing; wrap every stream, including unknown-length providers, in a counting limiter. Abort and roll back once any aggregate budget is reached, and keep progress counters as Long.
