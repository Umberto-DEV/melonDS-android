# Zero-width DSi graphics command underflows a native transfer length

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_595441428ec94336e7c4ebf7` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android enables DSi DSP HLE. The graphics microcode accepts a one-third scaling command with width zero and height three because zero is divisible by three. It then calls 'ReadARM9Mem()' with length zero.
- **Attack path:** guest DSP command parameters -&gt; zero-width scaling -&gt; zero-length native copy -&gt; unsigned wrap -&gt; raw NWRAM writes
- **Evidence and proof level:** **static** in the sealed finding (`validated`): static arithmetic and guest-command dataflow proof; One-third validator accepts zero width; Zero is divisible by three, so width zero and height three pass. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — nearest/bilinear/bicubic/one-third/YUV controls pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The width upper bound does not reject zero, and the multiple-of-three comment does not establish a positive lower bound.
- **Limitations:** No ASan runtime PoC was executed.
- **Recommended correction:** Reject zero or undersized graphics dimensions before dispatch. Make zero-length memory transfers no-ops, validate the alignment prefix against the remaining length, and pass a bounded destination span rather than a raw pointer. Add equivalent minimum-size and overflow checks to every scaling mode.
- **Disposition, patch and before/after:** Validate each scaling handler's dimensions/buffers and use wide products **Before:** zero/small widths underflowed increments and transfer lengths **After:** nearest/bilinear/bicubic/one-third/YUV controls pass Recorded integration pair: [app a77ccaaa](https://github.com/Umberto-DEV/melonDS-android/commit/a77ccaaac5ca99f4ac1893b1dfb9b41326f75811); [core 65952aec](https://github.com/Umberto-DEV/melonDS-android-lib/commit/65952aec868bedd2dc33151ed850804e3e13df05).
