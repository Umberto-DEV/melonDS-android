# RetroAchievements responses can exhaust the Android heap before unbounded JNI mapping

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_f49486b60787daa20317b351` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** RetroAchievements GET and POST responses from the fixed HTTPS origin are read to EOF, parsed into a complete JSON tree, decoded into unbounded nested collections and strings, flattened and copied into Java arrays, and then passed to a JNI mapper with no per-call item budget.
- **Attack path:** game/login action -&gt; 'RAApi' request -&gt; server-controlled response body -&gt; 'readText()' -&gt; 'Json.parseToJsonElement()' -&gt; decoded collections
- **Evidence and proof level:** **static** in the sealed finding (`validated`): static source trace and control comparison; Normal game lookup refreshes remote hash data; Opening an achievements-enabled game can invoke 'getGameHashList()' during the daily refresh, making the remote response path reachable without a diagnostic or developer-only workflow. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The base URL is fixed to HTTPS and platform TLS validation narrows the attacker to a compromised service or TLS-trusted response source. No runtime oversized-response reproduction was authorized or performed.
- **Limitations:** The exact body size needed to terminate a specific Android device process was not measured. External service behavior and infrastructure limits were not contacted or assumed.
- **Recommended correction:** Enforce endpoint-specific compressed and decompressed byte ceilings while streaming every RetroAchievements response, reject missing or dishonest lengths at the counting boundary, and cap JSON depth, set/achievement/leaderboard counts, and expression/string lengths before model construction, flattening, or toTypedArray(). Keep those budgets below a safe JNI-call cardinality.
