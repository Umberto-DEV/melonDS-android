# A crafted custom firmware image can make checksum updates write outside its native buffer

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_a558a5b137d2433c0269cf8e` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android accepts DS firmware by exact file size and a console-type byte, but never validates the header's 'UserSettingsOffset'. Native helpers shift that attacker-controlled field to derive Wi-Fi and user-data pointers without comparing them to 'FirmwareBufferLength'; Android then unconditionally calls 'UpdateChecksums()' on externally loaded firmware.
- **Attack path:** Selected firmware -&gt; exact-size/type validation -&gt; native heap buffer -&gt; header-derived pointers -&gt; checksum writes
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static source trace from Android configuration validation through native firmware loading, pointer derivation, and checksum assignment.; Android validates expected size and console type but not internal offsets; Accepted exact lengths are checked, but the structural offset later used by native code is not. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — DS/DSi layout and underflow/EOF tests pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Android rejects firmware whose reported length is not an expected exact size. The user must opt into external firmware and select/place the crafted file.
- **Limitations:** Static validation only; exact crash/corruption behavior depends on allocator layout and Android memory protections. Validation was static because the read-only scan environment did not permit building an instrumented APK.
- **Recommended correction:** Validate the complete binary layout in native code before exposing any region: use checked arithmetic and require the basic Wi-Fi, optional extended Wi-Fi, and both user-data records to fit within 'FirmwareBufferLength'. Reject malformed images before customization; retain native checks even if Android also adds early validation.
