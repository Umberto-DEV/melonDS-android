# A malformed external firmware-launch intent crashes the Android emulator

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_a58108db986cc45682121731` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** EmulatorActivity is exported without a component permission and accepts firmware-launch extras from other applications. Both cold-start/saved-state and singleTask new-intent parsers index the two-element ConsoleType.entries array with a caller-controlled integer after rejecting only the sentinel -1.
- **Attack path:** external intent extra -&gt; 'LaunchArgs' integer -&gt; 'ConsoleType.entries[index]' -&gt; uncaught index exception
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static manifest-to-onNewIntent/saved-state tracing.; Independent offline Android source trace; Firmware launch is exported; Any local application can address the exported activity; no component permission is declared. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — malformed ordinal launch test passes. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Only local installed apps can invoke this path; direct impact is availability. Normal in-app builders provide valid ordinals.
- **Limitations:** No crash intent was sent or application code executed. No runtime crash reproduction was performed.
- **Recommended correction:** Do not use caller-supplied values as enum ordinals. Decode the external protocol with ConsoleType.entries.getOrNull() or an explicit stable-value when expression and return an invalid-arguments result for every unsupported value or type in both parsers before mutating or pausing a session.
