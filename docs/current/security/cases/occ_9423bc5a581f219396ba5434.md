# Launching a compressed ROM can exceed the configured cache limit and exhaust storage

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_9423bc5a581f219396ba5434` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** A third-party frontend or user can launch a readable ZIP or 7z ROM whose decoded entry exceeds the configured extracted-ROM cache maximum (128 MiB to 8 GiB). Archive metadata is used only for best-effort eviction: admission does not reject an entry larger than the quota or prove enough space was freed.
- **Attack path:** malicious archive -&gt; ZIP/7z decoded stream -&gt; eviction-only cache planning -&gt; unbounded FileOutputStream -&gt; externalCacheDir volume
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Semantic reconciliation of already-validated Standard findings; no repository inspection or runtime execution.; Independent offline static source trace; Extractor reports archive metadata size; Cache planning trusts entry metadata rather than observed output. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — oversize/truncation/quota JVM tests pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The output name is fixed inside externalCacheDir, so archive path traversal was rejected. SevenZ decoder memory now has a limit and OOM handling; this finding concerns decoded disk output and also applies to ZIP.
- **Limitations:** No live archive was generated or application code executed. Android/OEM storage reclamation and any filesystem quota were not reproduced; they affect final device-wide impact, not the missing application byte bound.
- **Recommended correction:** Make cache admission fail closed when the declared size is unknown, negative, larger than the lower of a fixed safe native ROM maximum and the full configured cache allowance, or cannot fit after verified eviction and reserved filesystem headroom.
