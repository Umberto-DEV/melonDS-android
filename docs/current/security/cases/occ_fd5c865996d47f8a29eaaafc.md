# GitHub builds contact GitHub after update checks are disabled

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_fd5c865996d47f8a29eaaafc` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The GitHub settings screen stores 'github_check_for_updates' in AndroidX's default SharedPreferences, but both GitHub update repositories read the same key from a separate 'preferences-github' file where it remains at the default 'true'.
- **Attack path:** User disables the switch in default preferences -&gt; repository reads absent key from 'preferences-github' as true -&gt; launcher initializes UpdatesViewModel -&gt; Retrofit requests the melonDS release path from 'api.github.com'
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static variant-aware trace from preference resource through dependency injection, repository gate, launcher caller and Retrofit origin.; Disabled preference explicitly permits the check; False has the opposite of the preference's declared meaning. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The destination is fixed HTTPS 'api.github.com'. The Play Store flavor uses a separate repository and has no update preference resource.
- **Limitations:** No runtime packet capture was performed. The scan did not contact GitHub or any external service.
- **Recommended correction:** Use one injected SharedPreferences instance for both the settings screen and update repositories (or configure the PreferenceManager to the same named file before inflating the screen), and change the production disabled branch to return 'false'. Keep cadence metadata in that same deliberate namespace or a separate internal store without duplicating the user-controlled boolean.
