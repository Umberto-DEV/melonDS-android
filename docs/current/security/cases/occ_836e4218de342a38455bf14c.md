# A DSi DSP DMA length can wrap its progress counter and hang the emulator thread

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_836e4218de342a38455bf14c` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Teakra executes DSP DMA synchronously in 'while (running)'. In double-word mode the 16-bit inner counter advances by two and is compared to a guest-controlled 16-bit 'size0'; when 'size0' is '0xFFFF', the counter visits only even values and wraps from '0xFFFE' to zero, so the termination hierarchy is never reached and the Android emulator thread remains in the native loop.
- **Attack path:** guest DSP MMIO -&gt; DMA size/mode fields -&gt; SetZ trigger -&gt; DoDma while-loop -&gt; u16 counter wrap -&gt; nontermination
- **Evidence and proof level:** **static** in the sealed finding (`status not specified`): Static arithmetic proof and guest-MMIO trace; DMA runs synchronously until running clears; There is no iteration budget or asynchronous scheduling; termination depends entirely on 'Tick()' clearing 'running'. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Most sizes terminate, including lower odd values because the even counter overshoots them before wrapping. The path requires DSi mode and Teakra LLE/fallback.
- **Limitations:** No dynamic timing measurement was performed; nontermination is proven from finite-width arithmetic.
- **Recommended correction:** Use a wider progress counter or compute completion without wraparound; explicitly reject size/step combinations that cannot terminate. Replace the unbounded synchronous loop with a bounded/scheduled execution budget and fail closed on impossible state.
