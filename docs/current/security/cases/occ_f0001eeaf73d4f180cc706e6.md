# A truncated DSiWare file can create an invisible, non-reimportable NAND title

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_f0001eeaf73d4f180cc706e6` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `cross`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android's DSiWare preflight requires only eight title-identity bytes at offset '0x230'. The core later asks for a 4 KiB 'NDSHeader' but ignores whether that read completed; the zero-initialized remainder permits structure creation, and the short app file is copied successfully.
- **Attack path:** A user selects an attacker-supplied 0x238-byte DSiWare file with valid identity bytes; melonDS persists a TMD and short app, reports success, then hides the title and refuses reimport.
- **Evidence and proof level:** **static** in the sealed finding (`status not specified`): Static constructible-file and persistent-state trace; Android import preflight needs only eight bytes at 0x230; A 0x238-byte file can satisfy the only local-file validation when its final eight bytes match the fetched TMD identity. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — short metadata/header and cleanup tests pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The DSiWare manager activity is non-exported. TMD and application title identities must match.
- **Limitations:** The file was not imported into a test NAND at runtime.
- **Recommended correction:** Before any NAND mutation, require the source length to cover 'NDSHeader', validate the exact header read, TMD content size/hash, title identity and structural offsets. Stage the complete title and publish it atomically only after every validation/write succeeds. Make listing, existence and deletion use a consistent validity model and expose cleanup for invalid partial titles.
