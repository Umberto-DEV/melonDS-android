# DSiWare metadata is imported from cleartext HTTP without authenticity verification

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_7912862fc50149068674e372` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** During a user-initiated DSiWare import, the app explicitly downloads the title's signed 520-byte metadata over permitted cleartext HTTP and treats those bytes as authoritative.
- **Attack path:** selected local DSiWare title IDs -&gt; cleartext HTTP request -&gt; attacker-modified same-title TMD -&gt; JNI identity guard -&gt; NAND title.tmd and versioned .app path
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static source tracing from the Android metadata repository through JNI validation into native NAND installation.; Independent offline source trace; Cleartext TMD download; The full metadata structure is fetched over unauthenticated HTTP. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — HTTP is rejected before openConnection; HTTPS injected transport passes. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The JNI check binds category/title ID to the selected local title. The filename is formatted as fixed-width hexadecimal and does not permit path traversal.
- **Limitations:** No claim is made that altered metadata yields host-native code execution or cross-title access. No host-code-execution path from forged TMD fields was established.
- **Recommended correction:** Use authenticated transport where the endpoint supports it and independently verify the Nintendo TMD RSA signature/certificate chain against a pinned trusted key before import.
