# Teakra DMA active-channel MMIO accepts arbitrary array indices

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_2ef748460c8bc14f9e87a687` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Malicious DSi DSP microcode can write any 16-bit value to the active-channel MMIO selector and then use DMA register getters/setters to index beyond Teakra's eight-element channel array, causing native memory disclosure or corruption.
- **Attack path:** Untrusted DSi software loads DSP code that selects channel &gt;=8 through MMIO, then reads or writes a DMA property and reaches memory outside channels.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static source trace from DSP microcode fallback through MMIO to native array accesses; DSP MMIO exposes the active-channel setter and indexed registers; Guest DSP MMIO writes choose the selector and immediately expose channel-indexed properties. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** EnableChannel iterates only channel bits zero through seven. That bounded helper is separate from ActivateChannel and does not constrain the active selector.
- **Limitations:** No runtime microcode payload or exploitation was executed. Static review proves native out-of-bounds access, not reliable code execution.
- **Recommended correction:** Reject or mask active-channel values above seven in ActivateChannel, use checked channel accessors for every getter/setter, and validate active_channel during savestate restore.
