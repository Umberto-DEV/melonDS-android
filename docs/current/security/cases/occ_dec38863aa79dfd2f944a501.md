# Privileged release workflows execute dependencies without immutable integrity pins

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_dec38863aa79dfd2f944a501` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Release and nightly workflows reference third-party GitHub Actions by mutable version tags, including ncipollo/release-action@v1 and r0adkll/upload-google-play@v1.1.x in jobs that receive publication credentials. The Gradle wrapper also downloads a build distribution without distributionSha256Sum. A moved or compromised upstream reference can therefore execute inside trusted signing/publication jobs.
- **Attack path:** mutable action tag or unverified distribution -&gt; trusted release runner -&gt; signing/publication job context -&gt; secrets/artifacts/release destination
- **Evidence and proof level:** **static** in the sealed finding (`status not specified`): static workflow configuration review; Nightly publisher uses a mutable major tag; The action code selected by mutable @v1 executes in a job with a write-capable GitHub token after the keystore-bearing build step. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — automated policy reports zero violations. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** No separate item was recorded in the sealed finding.
- **Limitations:** Repository-level environment protections and secret scopes are not present in source. The exact permissions of the Play credential are unknown.
- **Recommended correction:** Pin every GitHub Action to a reviewed full commit SHA and use dependency automation to propose audited updates. Add the official distributionSha256Sum for Gradle 9.7.1. Isolate signing from publication where practical, minimize per-job token permissions, and place production publication behind protected environments/approvals.
