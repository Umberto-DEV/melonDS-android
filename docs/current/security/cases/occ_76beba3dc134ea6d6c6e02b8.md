# Loading a crafted RetroAchievements definition can make Android read across an emulated-memory region boundary

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_76beba3dc134ea6d6c6e02b8` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** RetroAchievements definition strings supplied by the remote achievement-set response reach rcheevos unchanged. A definition can select a 16- or 32-bit read at an unaligned or final byte of Main RAM or ARM9 DTCM; 'PeekMemory()' masks only the starting offset and then dereferences a 'u16*' or 'u32*', so the complete span is not constrained to the selected 'std::array' and C++ alignment requirements are not enforced.
- **Attack path:** RetroAchievements 'MemAddr' -&gt; DTO/model/JNI -&gt; rcheevos width dispatch -&gt; 'PeekMemory()' -&gt; typed read across an array boundary
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Offline static source trace against the current Android app, bundled rcheevos, and nested core; Remote DTO accepts an unrestricted memory expression; The achievement-set response controls 'memoryAddress'; the DTO imposes no address-range, alignment, or complete-span constraint. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The fixed service is the definition authority; arbitrary publication is not proven. Adjacent objects are emulated memory, not demonstrated host secrets.
- **Limitations:** Static validation only; upstream publication controls and Android runtime behavior were not exercised.
- **Recommended correction:** Validate the full '(region, offset, width)' span before each RetroAchievements read and assemble values byte-wise or with 'memcpy' so no under-aligned typed pointer is formed; reject definitions whose operands cross a supported region before activation.
