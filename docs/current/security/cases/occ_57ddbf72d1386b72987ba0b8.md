# A crafted DSi ROM can read past SD/MMC response objects into host memory

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_57ddbf72d1386b72987ba0b8` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** 'DSi_SDHost::DataRX()' replaces a device-supplied response length with the guest-programmed 'BlockLen16'. ACMD13 and ACMD51 pass fixed 64-byte SSR and 8-byte SCR arrays, but a crafted DSi title can set the block length as high as 512, causing the native loop to read hundreds of bytes beyond those arrays and return them through the emulated FIFO.
- **Attack path:** guest BlockLen16 register -&gt; ACMD fixed response -&gt; DataRX length substitution -&gt; out-of-bounds native loads -&gt; guest FIFO Additional corroboration: guest SD/MMC registers -&gt; 'SendACMD()' fixed response -&gt; 'DataRX()' length replacement -&gt; out-of-bounds source reads -&gt; 'ReadFIFO16()' Additional SDIO subpath: guest block length and short CMD53 -&gt;…
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static source trace from DSi SD/MMC MMIO through ACMD fixed responses to guest FIFO; Guest controls the receive block length; The guest can set any length up to 512 bytes, including values larger than fixed protocol response objects. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** FIFO::Write stops when full, but 512 bytes fit its 256-word capacity and this does not bound the source allocation. Well-behaved firmware programs matching response lengths; malicious guest code need not.
- **Limitations:** Static validation only. Exact bytes beyond the object depend on C++ layout and allocator state.
- **Recommended correction:** Make the caller-supplied source capacity authoritative. Reject block-length mismatches or copy only 'min(protocol_length, BlockLen16)' while reporting a protocol error; use a span or explicit capacity parameter and handle odd byte lengths without a two-byte overread. Additional merged remediation requirements: Keep the producer-supplied source length authoritative.
