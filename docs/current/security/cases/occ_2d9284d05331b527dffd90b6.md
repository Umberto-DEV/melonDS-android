# Unrestricted tag pushes reach production signing and GitHub publication

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_REPOSITORY_EXTERNAL_CONTROL_UNVERIFIED`.

- **Identity and status:** `occ_2d9284d05331b527dffd90b6` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `high` · layer `app`. Repository control applied; production environment absent from the GitHub API results; tag protection unverified. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The production release workflow runs for every pushed tag except 'nightly-release' and has no actor, repository, protected-environment, or approval condition. It checks out the tagged source, exposes the Android production keystore and passwords to Gradle executed from that source, and publishes the resulting signed APK through 'GITHUB_TOKEN'.
- **Attack path:** tag push -&gt; checkout tag-selected source -&gt; write keystore/passwords -&gt; execute Gradle -&gt; sign APK -&gt; release-action publication
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent workflow inventory followed by source tracing and prior-ledger reconciliation; Every non-nightly tag triggers production release jobs; The workflow matches every pushed tag except one literal nightly tag and has no repository, actor, or protected-environment condition. Disposition evidence: **mixed**: repository checker executed; external control unverified — Repository integrity policy passes; GitHub API follow-up found production environments absent; tag protection remained unverified. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Actions are pinned to immutable commits and the Gradle distribution is checksum-pinned. External protected-tag or repository-token rules could reduce reachability, but the workflow does not bind to a protected environment.
- **Limitations:** Repository settings and GitHub environment rules were not queried by explicit offline constraint.
- **Subsequent configuration check:** The GitHub API read after the scan lists no environments in the fork and only `copilot` upstream; `production-github-release` is not configured. The repository gate prevents the fork from running the job; the upstream code requires the specified actor. The tag-protection API returned 404, which does not establish effective tag protection; [Details](../SECOND-CAMPAIGN.md).
- **Recommended correction:** Build the artifact without signing secrets, record its digest, and promote only that digest in a minimal signing/publishing job bound to a protected production environment with required reviewers. Restrict release tags to an authorized release identity, declare explicit least-privilege permissions, and disable checkout credential persistence during untrusted build execution.
