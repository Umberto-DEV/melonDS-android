# G.711 output to SCFG_RST can delete the executing DSP HLE object

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_86c50141e68ec4d1fcff078f` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The Android-enabled G.711 DSP HLE accepts a guest-controlled 32-bit destination and writes decoded samples with 'DSi::ARM9Write16'. Choosing '0x04004006' routes the first write to 'DSP.SetRstLine', whose unconditional 'Reset()' deletes 'DSPCore'—the currently executing 'G711Ucode'. Control returns to its decode method and then 'FinishCmd', which continues reading members and calling methods through the freed 'this' pointer.
- **Attack path:** guest pipe destination/value -&gt; G711 decode -&gt; ARM9Write16 -&gt; SCFG_RST -&gt; DSP reset/delete -&gt; FinishCmd UAF
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static call-sequence and object-lifetime trace on the Android HLE configuration; Android selects DSP HLE; The final DSiArgs field is DSPHLE, so the Android DSi path uses the vulnerable HLE object. Disposition evidence: **post-fix suite and RED/GREEN for an adjacent refinement** — the ARM9 NWRAM window helper check was RED with exit 1, and all 29 G.711 ASan/UBSan checks are GREEN after the correction. That RED demonstrates a one-byte escape from the aperture, not this occurrence's SCFG_RST use-after-free. The object-lifetime sequence remains established by static analysis and has not been executed end to end on Android.
- **Counterevidence:** A one-sample command avoids the earlier unbounded-loop issue and makes the lifetime flaw independently reachable. The freed allocation may remain readable temporarily, but that is still undefined behavior and subsequent method calls can corrupt state.
- **Limitations:** No ASan/runtime reproducer was executed. Allocator reuse and exploitability were not measured.
- **Recommended correction:** Restrict codec source/destination spans to valid guest RAM ranges before starting commands. Make DSP reset/destruction reentrancy-safe by marking a pending reset and deleting/replacing the core only after the active callback unwinds; never continue FinishCmd if the core generation changed.
