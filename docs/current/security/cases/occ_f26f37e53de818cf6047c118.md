# Restored firmware text can crash generated-firmware startup

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_f26f37e53de818cf6047c118` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Settings restore accepts firmware nickname and message strings under a broad generic character cap. JNI converts Java UTF-16 to modified UTF-8 and byte-truncates it into 11- and 27-byte C arrays, which can split a multibyte sequence; supplementary and embedded-NUL forms also are not the standard UTF-8 assumed downstream.
- **Attack path:** settings.json -&gt; preferences -&gt; JNI modified UTF-8 -&gt; raw byte truncation -&gt; strict 'from_bytes' in noexcept
- **Evidence and proof level:** **static** in the sealed finding (`reportable`): Static source trace with local Android NDK libc++ verification; Restore accepts arbitrary type-correct strings; The backup is an untrusted document import and both firmware text keys are schema-known strings. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The analogous DSi override is dead code. Custom firmware skips these string conversions.
- **Limitations:** The trigger was not executed in Android. Exact behavior for every modified-UTF-8 edge case depends on the C++ standard-library implementation, but mid-sequence truncation is sufficient to produce invalid input.
- **Recommended correction:** Carry firmware nickname and message as length-aware UTF-16 from JNI, enforce the actual DS code-unit and supported-character limits before copying, and never byte-truncate UTF-8. Share normalization between UI and restore, reject or replace unsupported values, and catch any conversion failure before 'noexcept', returning a recoverable launch error or safe default.
