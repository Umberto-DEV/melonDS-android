# Running a crafted DSi ROM can read beyond the BPTWL register array into host memory

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_09abfa72b6bd218ba5427fa8` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `high` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** A crafted DSi ROM can drive the ARM7 I2C MMIO interface to select the BPTWL device and issue repeated reads after register '0xff', or read before selecting any register. 'DSi_BPTWL::Read()' indexes the fixed 256-byte 'Registers' array with the unchecked 32-bit 'CurPos' cursor and returns that byte to the emulated guest, allowing out-of-bounds host reads and process termination.
- **Attack path:** guest ARM7 MMIO writes -&gt; 'DSi_I2CHost::WriteCnt()' -&gt; 'DSi_BPTWL::Read()' -&gt; unchecked 'Registers[CurPos]' -&gt; I2C data MMIO read Additional corroboration: guest ARM7 I2C MMIO -&gt; 'DSi_I2CHost::WriteCnt()' -&gt; 'DSi_BPTWL::Read()' -&gt; 'Registers[CurPos]' -&gt; I2C data MMIO
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static source trace of the Android-compiled DSi ARM7 MMIO, I2C host, BPTWL device, and result path; Guest writes reach the DSi I2C host; Guest ARM7 byte writes control the I2C data byte and control flags that select a device and initiate transfers. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Well-behaved DSi software selects a valid register before reading. Writes are restricted to enumerated registers, but the read path has no equivalent allowlist or range check.
- **Limitations:** Validation is static because the authorized scan is read-only and did not execute a crafted ROM. Exact disclosed bytes depend on object and allocator layout.
- **Recommended correction:** Reject or safely NACK a BPTWL read unless 'CurPos &lt; sizeof(Registers)' before the array access; define explicit auto-increment/wrap behavior, initialize transaction state in 'Acquire()', and reset or invalidate the cursor consistently at transaction boundaries. Apply the same domain check during savestate restoration so invalid cursors are rejected before commit.
