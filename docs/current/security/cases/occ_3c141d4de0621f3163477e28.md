# Malformed DSi NAND reads expose uninitialized host memory during boot

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_3c141d4de0621f3163477e28` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android opens a user-selected DSi NAND read/write and configures non-full-BIOS boot. The core ignores raw NAND read results and FatFs byte counts, then copies or decrypts uninitialized stack buffers into guest ARM memory. Crafted boot parameters can also drive extreme loop counts. This is a new cause, separate from the prior 35 occurrences.
- **Attack path:** SAF nand.bin -&gt; NANDImage -&gt; Reset/LoadNAND or direct boot -&gt; unchecked read -&gt; uninitialized local -&gt; ARM guest RAM
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static Android-to-core reachability and sink validation; Android opens configured NAND; A user-selected content-backed NAND becomes the core NANDImage after only the constructor's limited validity checks. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** DSi-only and requires mounted user NAND. DSiWare direct boot uses a different branch.
- **Limitations:** No truncated NAND record was executed. No crafted NAND was booted under the read-only mandate.
- **Recommended correction:** Initialize every read destination, require exact successful reads and seeks before consuming data, validate boot offsets/sizes against NAND length and maximum boot-section limits, and abort boot atomically on failure.
