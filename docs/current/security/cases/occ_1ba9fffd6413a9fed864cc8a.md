# DSi NWiFi BMI commands run up to 2^32 guest-selected iterations

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_1ba9fffd6413a9fed864cc8a` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `core`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** During DSi Wi-Fi boot phase 0, guest-written mailbox commands 'BMI_WRITE_MEMORY' and 'BMI_LZ_DATA' copy an untrusted 32-bit length directly into synchronous native loops. Neither case compares the declared length with remaining mailbox bytes or a protocol ceiling, and an empty 'DynamicFIFO::Read()' keeps returning without terminating, so a short command can request nearly 2^32 iterations.
- **Attack path:** guest CMD52 mailbox writes -&gt; 'F1_Write()' -&gt; phase-0 'BMI_Command()' -&gt; declared-length loop -&gt; non-failing empty FIFO reads
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Offline static source trace of DSi SDIO mailbox dispatch and FIFO behavior; Guest writes dispatch mailbox zero; Function-1 writes populate the command mailbox and a terminal address invokes command parsing. Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Only boot phase 0 reaches BMI. Uploaded bytes are currently discarded, limiting demonstrated impact to availability.
- **Limitations:** No malicious guest command was executed under the read-only scan. Exact boot-phase timing and runtime denial-of-service behavior were not exercised.
- **Recommended correction:** For every BMI payload command, reject the command unless the declared length is within both 'Mailbox[0].Level()' and a small protocol-specific maximum before entering a loop; make truncation/empty reads abort the command and share one bounded-payload helper across opcodes.
