# G.711 DSP commands can trap the Android emulation thread in billions of iterations

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_ac89863ef8213945c0ee1634` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Bound the G.711 sample count and perform timing arithmetic in a checked wide type before accepting a DSP HLE command. The DSi guest supplies a 32-bit length that is multiplied with wrapping u32 arithmetic and later controls four synchronous per-sample loops, allowing a malicious title to freeze or terminate the Android app.
- **Attack path:** A malicious DSi title loads a recognized G.711 DSP program, writes a command whose sample count is near UINT32_MAX, and triggers a completion event whose handler monopolizes the emulation thread.
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent source-to-sink trace from Android DSi configuration through ucode selection and each G.711 loop, reconciled against the previous 35-occurrence remediation ledger; Android enables DSi DSP HLE; The final true initializes DSiArgs::DSPHLE; DSi's constructor passes it to SetDSPHLE. Disposition evidence: **post-fix suite and RED/GREEN for an adjacent refinement** — the ARM9 NWRAM window helper check was RED with exit 1. After the correction, `bash tools/host-tests/security/run.sh` makes all 29 G.711 ASan/UBSan checks GREEN, including the work budget, exact boundary and one-byte escape; compilation of `G711Ucode.cpp` is recorded separately. That RED demonstrates escape from the NWRAM aperture. It does not reproduce the oversized command end to end on Android: the scan trigger remains supported by static source analysis, and NDK/ART results remain separate evidence.
- **Counterevidence:** The path requires DSi mode and a G.711 DSP program/command. Emulated addresses wrap according to normal memory access behavior; no host out-of-bounds access was established.
- **Limitations:** No long-running malicious command was executed because the campaign is read-only and avoids denial-of-service reproduction.
- **Recommended correction:** Define a protocol-compatible maximum G.711 sample count based on mapped source/destination spans and an explicit per-command work budget. Validate it before setting CmdState. Compute timing in u64, reject values that cannot be represented safely by the scheduler, and make FinishCmd revalidate restored command state before any loop.
