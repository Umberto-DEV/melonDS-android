# Enabling a crafted Action Replay cheat can freeze the Android emulator for billions of operations

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_95b372be5c7a53614199db50` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition. **Action Replay note:** final core `ac5e6ba0` includes the fairness refinement introduced by `6dec124b`; the host RED/GREEN below tests that refinement, not Android execution of the original trigger.
- **Summary:** Android accepts imported or manually entered Action Replay words, forwards enabled cheats to the native core and executes them synchronously on ARM7 VBlank. The interpreter has no instruction or guest-memory-operation budget: opcode 'C0' copies an untrusted 32-bit loop count that 'D1'/'D2' can replay, while 'F0' copies an untrusted byte count, so a tiny enabled cheat can monopolize the emulator thread.
- **Attack path:** usrcheat/custom words -&gt; enabled Room record -&gt; JNI 'u32' vector -&gt; native 'ARCode' -&gt; VBlank 'RunCheats()' -&gt; unbounded loop/copy
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Offline static dataflow and control-flow validation of Android cheat import, JNI mapping and native interpreter; Imported cheat words are size-bounded but semantically unrestricted; A database author controls every 32-bit word. Disposition evidence: **dynamic fairness-refinement RED/GREEN using the actual core** — `bash tools/host-tests/cheats/run.sh frame-fairness` exited with code 10 before the correction and is GREEN afterward: repeated IRQs in the same frame do not replenish the budget, the next frame resumes the deferred cheat, and `Enabled` remains consistent. All 14 ASan/UBSan modes are GREEN outside the sandbox. This check does not execute the billion-iteration payload or replace an Android NDK/ART test of the original trigger, which remains supported by source analysis.
- **Counterevidence:** Cheat storage is capped and paired instruction words are bounds-checked. Imported entries initially have 'enabled=false'.
- **Limitations:** No denial-of-service payload was executed because runtime execution was outside authorization.
- **Recommended correction:** Enforce a shared per-cheat and per-frame budget that counts decoded instructions, loop back-edges and guest-memory operations; abort and disable/quarantine the cheat with a user-visible error when the budget is exhausted. Dedup-0028 refinement: check stop/cancellation at bounded intervals as well as enforcing the per-frame operation budget.
