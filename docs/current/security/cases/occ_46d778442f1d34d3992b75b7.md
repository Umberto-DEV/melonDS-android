# Running a ROM can proxy traffic to Android localhost and private-network services

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_46d778442f1d34d3992b75b7` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `core`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** Android unconditionally gives the emulated console a bundled libslirp driver. Its zero-initialized configuration does not enable restricted mode or disable host loopback, and guest Wi-Fi Ethernet frames are passed to slirp_input. A malicious ROM can therefore originate TCP/UDP connections from the Android device to localhost or reachable private-network services.
- **Attack path:** Guest TCP/UDP packet to 10.64.0.1 -&gt; Android Net_Slirp -&gt; libslirp vhost translation -&gt; 127.0.0.1 -&gt; host connect()/sendto()
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static end-to-end tracing of Android driver construction, guest Wi-Fi forwarding, bundled libslirp configuration, and socket translation.; Unconditional Android Slirp driver; The Android configuration path always installs Net_Slirp without consulting a network-enable policy. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — policy enabled in production and network suite passes. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** The victim must run attacker-supplied code. No app-private filesystem access follows directly.
- **Limitations:** No live Android packet reproduction was run because application execution is outside this audit. No particular listening host service was established from repository source.
- **Recommended correction:** Set disable_host_loopback=true and apply a fail-closed destination policy that blocks loopback, link-local, RFC1918, carrier-grade NAT, multicast/broadcast abuse, and IPv6 ULA/local ranges unless the user explicitly enables local-network access. Keep ordinary Internet access separately configurable.
- **Disposition, patch and before/after:** Disable host loopback and reject private/local destinations in slirp policy **Before:** guest traffic could reach host/private services **After:** policy enabled in production and network suite passes Recorded integration pair: [app a77ccaaa](https://github.com/Umberto-DEV/melonDS-android/commit/a77ccaaac5ca99f4ac1893b1dfb9b41326f75811); [core 65952aec](https://github.com/Umberto-DEV/melonDS-android-lib/commit/65952aec868bedd2dc33151ed850804e3e13df05).
