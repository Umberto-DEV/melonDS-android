# Android save-sidecar loading can allocate nearly 4 GiB from a provider-controlled or failed length

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_f3a0f11c9bc863db1b13f85f` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The active NDS and optional GBA loaders size native allocations directly from selected or derived save-sidecar documents before the core knows the cartridge's supported save size. Both narrow unchecked descriptor lengths to 'u32' and call throwing 'std::make_unique&lt;u8[]&gt;' without a format limit or contained failure path.
- **Attack path:** SAF save document -&gt; URI file descriptor -&gt; FileLength -&gt; u32 narrowing -&gt; make_unique array allocation Additional corroboration: selected document tree -&gt; derived '.sav' URI -&gt; JNI string -&gt; 'FileLength' -&gt; 'std::make_unique&lt;u8[]&gt;'
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Independent static trace from Android SAF document selection through JNI to active NDS/GBA allocation sinks Additional corroboration: Offline source trace and exact comparison with prior occurrences occ_d861c760cdbcae81657434c1 and occ_c9523ca984164c679e7340bb.; The save file is resolved from a configured… Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** The document must be writable and located in the user-configured save tree. Lengths above UINT32_MAX wrap rather than allocate the full raw size; attacker can select a large value below 4 GiB.
- **Limitations:** Static validation only. Actual allocation behavior depends on device memory and overcommit.
- **Recommended correction:** Centralize NDS/GBA sidecar loading in one checked helper. Obtain length in a checked 'u64', treat every seek/tell failure as an error, and reject before narrowing or allocation unless it fits the supported cartridge save sizes and a conservative global maximum. For unknown or non-seekable providers, use bounded streaming.
