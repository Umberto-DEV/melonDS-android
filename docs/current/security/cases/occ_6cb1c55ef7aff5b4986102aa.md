# RetroAchievements bearer token is included in Android platform backup

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_6cb1c55ef7aff5b4986102aa` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** AndroidRAUserAuthStore saves the RetroAchievements bearer token in the app's default SharedPreferences. The application enables Android backup and defines neither fullBackupContent nor dataExtractionRules exclusions, so the preference file is eligible for platform cloud/device-transfer backup even though the separate manual settings exporter explicitly excludes the same credential.
- **Attack path:** RA login token -&gt; default SharedPreferences ra_token -&gt; default platform backup dataset -&gt; backup/restore recipient
- **Evidence and proof level:** **static** in the sealed finding (`validated_with_deployment_prerequisite`): static configuration and dataflow review; Application opts into platform backup without rules; No fullBackupContent or dataExtractionRules attribute narrows the default Android backup dataset. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — migration and backup-rule tests pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Android backups are normally protected by the user's account/device controls; users or device policy may disable backup; Android version and OEM transport affect actual inclusion and restore behavior. No live backup was inspected.
- **Limitations:** The actual backup transport, server-side protections, device lock state and restore behavior were not observable from source. Runtime backup contents and transport configuration were not observed.
- **Recommended correction:** Add dataExtractionRules for Android 12+ and fullBackupContent rules for older supported versions that exclude the default preference file or specifically isolate credentials in an excluded file. Prefer storing the token encrypted with a device-bound key that is not backed up, and invalidate tokens on suspicious restore or device changes.
- **Disposition, patch and before/after:** Move RA auth to dedicated preferences and exclude it from both Android backup mechanisms **Before:** bearer token shared backup-eligible preferences **After:** migration and backup-rule tests pass Recorded integration pair: [app a77ccaaa](https://github.com/Umberto-DEV/melonDS-android/commit/a77ccaaac5ca99f4ac1893b1dfb9b41326f75811); [core 65952aec](https://github.com/Umberto-DEV/melonDS-android-lib/commit/65952aec868bedd2dc33151ed850804e3e13df05).
