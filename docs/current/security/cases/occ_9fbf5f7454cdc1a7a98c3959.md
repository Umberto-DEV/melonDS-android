# DSi title listing reads fixed-width banner text as an unbounded string

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_9fbf5f7454cdc1a7a98c3959` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `cross`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The Android DSiWare manager lists titles by reading header/banner structures from the user-selected writable NAND and converting banner.EnglishTitle with a null-terminated overload. EnglishTitle is a fixed 128-code-unit field, but neither the NAND reader nor JNI caller requires a terminator or complete reads; the stack structures are also left uninitialized on early/partial failure.
- **Attack path:** crafted DSiWare .app -&gt; NAND title import -&gt; fixed NDSBanner read -&gt; unbounded to_bytes(pointer) -&gt; stack over-read/termination
- **Evidence and proof level:** **static** in the sealed finding (`validated`): Static Android DSi manager to native NAND/title conversion tracing.; Android DSi title listing; Opening/listing DSiWare titles invokes getTitleData for each NAND-controlled title. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — short banner and bounded-title JNI tests pass. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Zero BannerOffset clears banner memory. Normal metadata is generally well formed.
- **Limitations:** No crafted NAND was executed and no sensitive stack disclosure was demonstrated. No JNI output/sanitizer reproduction was run.
- **Recommended correction:** Zero-initialize header/banner objects, make GetTitleInfo return a checked success status, validate every seek, banner offset, exact read count, and file extent, and convert only [EnglishTitle, EnglishTitle + 128) trimmed at the first NUL. Treat invalid UTF-16 or conversion exceptions as recoverable per-title metadata errors before crossing JNI.
