# Signing in can expose RetroAchievements passwords and tokens through URL logs

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED`.

- **Identity and status:** `occ_f39613af9fae3c25d83a0055` · scan `4c41e000-6ba0-4453-aaa7-3cdbec542687` · severity `medium` · layer `app`. Technical disposition from CSV: CORRECTED. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** 'RAApi.login()' places the user's plaintext password in an HTTPS GET query, and multiple authenticated operations place the bearer token in GET queries. 'buildGetRequest()' appends all encoded values to the full URL, making the secrets eligible for routine URL logging by the service, reverse proxies, TLS-inspection infrastructure, diagnostics, or crash/monitoring systems.
- **Attack path:** user password or stored token -&gt; GET parameter map -&gt; URL encoding -&gt; full request URL -&gt; external URL logs/telemetry
- **Evidence and proof level:** **static** in the sealed finding (`validated`): static secret-source-to-request-sink trace; Login sends the plaintext password through the GET helper; The user-entered password is stored under query parameter 'p' and passed to the generic GET request builder. Disposition evidence: **recorded dynamic post-fix checks**; pre-fix evidence remains static unless the report records an explicit RED — RA API tests assert secrets absent from URLs. No dynamic RED is inferred unless the report records it explicitly.
- **Counterevidence:** Passive network observers cannot read the HTTPS query without breaking or terminating TLS. The app's configured interceptor adds only a User-Agent and does not log requests.
- **Limitations:** The audit did not contact RetroAchievements or inspect its server-side logging/redaction policy. No service or deployed logging configuration was inspected.
- **Recommended correction:** Move login and every token-bearing operation to form-encoded POST bodies or a supported authorization header, prohibit cross-origin credential forwarding on redirects, and redact parameters 'p' and 't' in all client/server/proxy/telemetry layers.
