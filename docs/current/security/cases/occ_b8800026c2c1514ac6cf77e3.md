# Provider write exceptions cross JNI unchecked and poison the native save worker

[Security index](../README.md) · [Disposition register](../FINDINGS.csv)

**Canonical disposition:** `CORRECTED_SECOND_SCAN`.

- **Identity and status:** `occ_b8800026c2c1514ac6cf77e3` · scan `ab26b107-97dd-4557-9c4b-2942e5df879d` · severity `low` · layer `app`. Technical disposition from CSV: CORRECTED_SECOND_SCAN. The Security UI state may remain **Open**; it is separate from the technical disposition.
- **Summary:** The Kotlin URI bridge catches any Exception for reads but catches only FileNotFoundException in write branches; fileExists, document creation, or openFileDescriptor can throw SecurityException and other provider/runtime exceptions. UriFileHandler::open calls the method without ExceptionCheck and interprets the default jint result as a file descriptor.
- **Attack path:** A selected/revoked content provider throws during a write-side existence query or open; the exception crosses the JNI call and the native save worker treats the default return as a descriptor.
- **Evidence and proof level:** **static** in the sealed finding (`confirmed`): Static exception-flow review across ContentResolver/DocumentFile, Kotlin, JNI, and the persistent native worker.; Write operations catch only FileNotFoundException; Write-mode provider queries and opens can propagate SecurityException, IllegalArgumentException, RemoteException wrappers, or provider runtime… Disposition evidence: **recorded post-fix class/suite tests, without an individual dynamic reproduction of the trigger** — Focused regression plus final host/JVM/NDK/ART checks recorded in the second-campaign report. This card is supported by source analysis unless it cites a specific RED/GREEN result; aggregate final checks are not counted as an individual finding GREEN.
- **Counterevidence:** Read-mode opens catch Exception and map it to -1. FileNotFoundException is handled in the inner write opens.
- **Limitations:** No malicious ContentProvider or revoked-grant CheckJNI instrumentation was executed. ART's exact return value and failure timing with the pending exception were not observed.
- **Recommended correction:** Wrap the complete Kotlin open operation—including fileExists and document creation—in a consistent exception boundary that maps expected provider/security failures to -1.
